    Host call sequence

    snapshot = born(...)
snapshot = decide(snapshot, permitted_context, candidate_actions, world_tick)
host executes snapshot.pending.candidate using environment and containment
snapshot = observe(snapshot, trusted_outcome_receipt)
host persists the decision/outcome and snapshot
child = born(..., parents=(snapshot,), tick=current_world_tick)
child = teach(snapshot, child, context_key, skill_key, current_world_tick)

    The birth call in the last two lines requires a mature living parent. These are API descriptions, not an executable demo or a way around Sandbox. BrainSnapshot.model_dump_json() and BrainSnapshot.model_validate_json() provide serialization; persistent filesystem/database storage and the population scheduler remain pending.

    Only the host creates candidate permissions, time, observations, receipts and assessments. The agent may propose content but cannot mark its own outcome verified. Snapshot immutability is not authentication. Persistent receipts need versioned run IDs, signed or protected provenance, exactly-once transition IDs, and crash-safe atomic append before production use.

    Critical subsystem interfaces

    • environment: map legal observations to normalized eight features; execute legal actions; produce independently checked outcome vectors and evidence IDs. Track actual time and needs.
    • economy: enforce resource/birth costs and parent teaching budgets; convert manual evidence into bounded advice records only through host checks.
    • exploration/library: store generated hypotheses and verified skills separately; hypothesis success is not automatically policy competence. Execute generated code only inside Sandbox.
    • predictor: predict future observations/actions, not hidden birth equations unless in a privileged evaluation condition. Scripted drive labels do not establish true mental intent.
    • containment: authority independent of drive scores; no direct filesystem/network capability in the numerical core. Firecracker is a KVM microVM; gVisor is a different isolation design, not a hardware microVM by definition. Backend deployment remains a separate gate.
    • recognition: optional learned proposal prior; cannot promote rules, manipulate evidence or replace the authoritative action validator.
    • evaluation: owns frozen budgets, splits, paired controls and validation receipts. Final test scores never become live evolutionary fitness.

    Start with child-scale tasks such as choosing between immediate consumption, saving, rest, social contact and skill practice. Labels alone must not determine rewards. Add conflicting incentives and scarce information only after the simple choice/feedback/teaching loop is measurable.

    Hardware and reproducibility

    No new dependencies or global settings. Numerical core is CPU-only and allocates no model. Shared quantized base inference, batched agent requests, bounded contexts and private memory are planned. The exact device called “AGX Spark” needs model/SKU confirmation before deployment sizing; do not assume its CUDA, ARM, virtualization or serving support from a nickname. Measure tokens/decision, latency, KV memory, training cadence and storage before choosing population size. One LLM call per simulated physics tick is not the scheduling model.

    Persist: full genome, versioned configuration, world and lineage IDs, context schema, action keys, policy/checkpoint hashes, snapshot, pending sequence, teacher evidence and assessment suite. Store secrets outside the repo. A population-wide snapshot must restore all agent clocks and event order, not just individual object state.
