# Individual training, cultural transfer and population evolution

## 1. Implemented baseline loop

The baseline is pure numerical policy adaptation, not neural self-training:

1. Host provides permitted observations, normalized context and bounded candidate actions.
2. `decide` updates eight activations, computes ratios, ranks legal candidates, and stores one
   pending decision with agent ID, sequence, world tick, outcome prediction and utility.
3. The environment executes the chosen action under independent constraints.
4. The trusted verifier produces an `Outcome` matching agent/sequence/action and a transition
   evidence ID. Text generated by the agent is not an outcome oracle.
5. `observe` consumes the matching pending receipt once and updates the context/skill estimate.
6. The host persists both decision and outcome; a later decision can change because of learning.

For each component of an existing outcome estimate:

    estimate_new = (1 - alpha) * estimate_old + alpha * observed_reward

The first observation initializes the estimate. Rewards are eight fixed, independently measured
world-outcome features in [-1,1]. This learns consequences; only action selection uses current
motivation ratios. It avoids replaying old scalar rewards under a changed preference vector.
There is no delayed-return credit assignment, counterfactual planner, gradient update, curiosity
bonus or replay trainer in v1. Greedy selection may fail to explore useful alternatives.

Knowledge is keyed by `(context_key, skill_key)`, which the host must version when dynamics or
action parameters change. Memory, knowledge, lesson and candidate counts have separate limits.
Knowledge eviction uses update recency, so forgetting is possible by design and must be measured.
Samples count real accepted receipts, not repeated optimizer passes. Duplicate recent evidence is
rejected; a global transition-ID deduplication store is still needed beyond the bounded window.

`verified=True` and assessment flags are **caller contracts**, not cryptographic proof.
Do not expose receipt construction or `observe` directly as model-callable tools. Serialized
snapshots and restored flags must come from trusted host storage.

## 2. Teaching loop

`teach(parent, child, context, skill, tick)` requires recorded parentage, living maturity, a
living learner, no pending actions, and personal parent evidence for the requested context/skill.
It transfers a capped advice item with source evidence; the parent's evidence is unchanged.
Repeated lessons replace the previous item for that teacher/context/skill rather than stacking
authority. A child can revise an incorrect lesson through its own action feedback.

Future richer teaching adds demonstrations, manuals, questions and exercises. The teacher chooses
what to demonstrate based on learning need and available budget; the learner must solve a different
task instance. Teach incorrect but plausible material as a robustness control. Receiving a book,
copying a sentence, or memorizing a demonstration is not measured skill acquisition.

## 3. Planned LLM self-training loop

Keep a shared frozen base and a versioned private adapter per learning agent where resources permit:

    collect trusted trajectories -> split by episode/world/lineage
    -> curate successes AND failures -> mix stratified historical replay
    -> train candidate adapter offline -> independent validation + retention + safety
    -> atomic checkpoint promotion or rejection -> resume next episode

- Start with supervised action/outcome prediction and behavior cloning of verified trajectories.
- Compare no-update, memory-only and adapter-update conditions at equal interaction/compute budgets.
- Add RL only for a stated planning objective. PPO-style updates need policy-version bookkeeping;
  arbitrary old trajectories cannot silently become on-policy data.
- Maintain scenario/rare-failure replay quotas. An external-data percentage is not a universal
  collapse cure; keep simulator, human-authored, model-generated and fantasy sources distinct.
- Check age-specific curriculum performance and old-task retention before promotion. The model
  cannot change the evaluator, reward extraction, birth genome or safety policy to raise its score.
- Do not expand LoRA rank merely because age increased. Capacity expansion is a separate proposal
  justified by measured benefit per additional memory/compute.
- Curriculum advancement requires observed competence; aging without training is a control.

This adapter pipeline is **planned**, not implemented by `observe`. LoRA supports efficient
adaptation, but does not itself guarantee continual-learning stability (Hu et al., 2021).

## 4. Population evolution

The new `DevelopmentArchive` implements bounded storage of externally evaluated mature snapshots
in fixed behavior cells. Its descriptor is measured behavior—not the eight birth coefficients.
A host assessment must match agent ID and validation-suite ID, be verified, pass safety, improve
over its declared baseline, and stay within a retention-drop limit. Within a cell only a better
score replaces the elite; a full archive refuses new cells. Rejected candidates remain the host's
responsibility to log; no history is automatically persisted by the archive.

The scheduler still must implement selection and trials:

1. Measure descriptor coverage, useful performance, cost and failure rates from completed runs.
2. Consider validated agents for the archive using the same fixed evaluation suite/budgets.
3. Select living mature parents with underrepresented behavioral niches and bounded lineage share.
4. Check world resources, population cap and cooldown; create a new child with inherited equations.
5. Run overlapping generations; parents can teach, but the child starts with no own evidence.
6. Evaluate descendants on validation worlds; retain improved or useful diverse variants.
7. Freeze the entire policy/archive for final unseen-world evaluation. Never use final test scores
   as repeated evolutionary fitness.

The implemented archive is a small MAP-Elites-inspired mechanism, not a claim of autonomous
open-ended evolution. Self-modified executable policy code remains disabled until the real
`Sandbox` backend exists. Numeric temperament sampling is not arbitrary code synthesis.

## 5. Growth versus reward hacking

Do not define evolutionary fitness as “satisfies sins most strongly.” Use evaluator-owned world
competence, adaptation and safety metrics. Report all eight outcome components, inactivity,
resource consumption, population extinction and teaching cost. A high Null agent must not earn
infinite positive reward for doing nothing; wait has a world-time/opportunity cost. Harmless
low-activity agents can occupy valid diversity niches without dominating fitness by inaction.


## 6. Upgraded Learning & Convergence Roadmap (Proposed — [ADR 0008](../../adr/0008-convergent-learning-and-hierarchical-planning-upgrade.md))

The current EMA + greedy-argmax baseline has no regret bound, no non-convex Pareto coverage,
one-step horizon, and assumes a stationary environment. Future milestones upgrade learning across
three strictly ablated tiers (without claiming general intelligence per `PRD.md` §4):

1. **Tier 1 (Uncertainty + Non-Convex MORL):** Track posterior variance in `SkillEstimate` for
   **UCB** (`auer2002ucb1`) / **Thompson Sampling** (`russo2018thompson`) exploration with
   sublinear regret, paired with **Chebyshev scalarization** (`vanmoffaert2014morl`) to cover
   non-convex multi-objective Pareto fronts.
2. **Tier 2 (Epistemic-Pragmatic Rollouts):** Replace one-step ranking with **Expected Free Energy**
   (`friston2015epistemic`, `parr2022activeinference`) and multi-step latent world-model MPC
   (`hafner2025dreamerv3`, `hansen2024tdmpc2`) inside `evolzen.predictor.planner`.
3. **Tier 3 (Hierarchical Options + Multi-Agent Stabilization):** Package verified `RuleLibrary`
   entries as temporal-abstraction **options** `(I, pi, beta)` (`sutton1999options`) and monitor
   multi-agent non-stationarity (`busoniu2008marl`) alongside CVT-MAP-Elites behavioral coverage.
